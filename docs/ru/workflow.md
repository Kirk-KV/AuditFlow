# Процесс аудита

[English](../workflow.md) | **Русский**

AuditFlow организует последовательность решений, а не заполнение форм ради форм.

```text
initial_data.yml
       ↓
planning_document.qmd + planning_decision.yml
       ↓
audit_program.yml
       ↓
workpapers + evidence
       ↓
observations
       ↓
report + feedback + archive
```

## Источники истины

| Этап | Основной артефакт | Назначение |
| --- | --- | --- |
| Исходные данные | `initial_data.yml` | Первоначальные цели, риски и периметр |
| Планирование | `planning_decision.yml` | Итоговое решение о рисках, контролях и подходе |
| Программа | `audit_program.yml` | Связь риска, контроля, теста и рабочего документа |
| Выполнение | `05_workpapers/*.qmd` | Доказательства, результаты и выводы |
| Наблюдения | `06_observations/*.yml` | Структурированные результаты аудита |
| Коммуникация | `07_reporting/report.qmd` | Итоговый отчет |
| Архив | `09_archive/audit_story.qmd` | Прослеживаемая история аудита |

Команды создают или обновляют производные документы. Ручной текст внутри защищенных блоков report и archive сохраняется при повторной генерации.

Фактические даты обновляются на основании событий AuditFlow. Они помогают анализировать ход аудита, но не должны блокировать работу.
